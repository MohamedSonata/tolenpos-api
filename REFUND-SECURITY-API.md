# 🔐 Refund Security System API

## Overview

Prevents refund fraud by requiring manager PIN approval for all refund requests. When a cashier initiates a refund, the system:
1. Stores the refund record with `pending` status
2. Sends push notification to license owner with 6-digit manager PIN
3. Admin reviews and provides PIN to cashier to complete refund

## Endpoint

### Add Refund Record

```
POST /api/key-seats/:documentId/refunds
```

**Authentication:** Required (JWT token)

**Description:** Adds a refund record to the seat's audit trail and notifies the license owner via FCM push notification.

#### Path Parameters

| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `documentId` | string | Yes | Document ID of the key-seat |

#### Request Body

```typescript
{
  originalReceiptNumber: string;      // Original sale receipt number
  transactionId: string;               // Unique transaction ID
  refundType: "full" | "partial";      // Type of refund
  refundAmount: number;                // Refund amount in currency
  requestedByUserId: number;           // Cashier/user ID requesting refund
  requestedByUsername: string;         // Cashier/user name
  managerPin: string;                  // 6-digit PIN (generated by POS client)
  reason: string;                      // Reason for refund
  terminalId: string;                  // Terminal/POS ID
  hoursSinceOriginalSale?: number;     // Time elapsed since original sale
  refundTimestamp?: string;            // ISO timestamp (defaults to now)
  itemsRefunded: Array<{               // Items being refunded
    productId: string;
    productName: string;
    quantity: number;
    unitPrice: number;
    totalPrice: number;
  }>;
}
```

#### Example Request

```bash
curl -X POST https://api.example.com/api/key-seats/abc123/refunds \
  -H "Authorization: Bearer YOUR_JWT_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "originalReceiptNumber": "REC-2024-001234",
    "transactionId": "TXN-ABC-123456",
    "refundType": "partial",
    "refundAmount": 45.99,
    "requestedByUserId": 5,
    "requestedByUsername": "cashier_john",
    "managerPin": "847293",
    "reason": "Customer returned damaged item",
    "terminalId": "POS-TERMINAL-01",
    "hoursSinceOriginalSale": 2.5,
    "itemsRefunded": [
      {
        "productId": "PROD-456",
        "productName": "Wireless Mouse",
        "quantity": 1,
        "unitPrice": 45.99,
        "totalPrice": 45.99
      }
    ]
  }'
```

#### Success Response (200 OK)

```json

  "data": {
    "refundRecordId": "12",
```

## Validation Rules

### Manager PIN
- Must be exactly 6 digits
- Numeric only (no letters or special characters)
- Generated by POS client (not backend)

### Refund Type
- Must be either `"full"` or `"partial"`

### Refund Amount
- Must be a positive number
- Must be greater than 0

### Required Fields
All of the following fields are mandatory:
- `originalReceiptNumber`
- `transactionId`
- `refundType`
- `refundAmount`
- `requestedByUserId`
- `requestedByUsername`
- `managerPin`
- `reason`
- `terminalId`

## Security Features

1. **Append-Only Records**: Refund records are appended to the `refundRecords` array, never modified or deleted
2. **Ownership Validation**: Only the seat's license owner can add refund records
3. **Status Tracking**: All refunds start with `pending` status
4. **Audit Trail**: Complete record of who requested, when, and what items
5. **Multi-Device Notification**: Pushes to all registered FCM tokens of license owner
6. **Time Tracking**: Records time elapsed since original sale

## Workflow

### POS Client Side
1. Cashier initiates refund request
2. POS app generates random 6-digit PIN
3. POS app collects refund details (items, amount, reason)
4. POS app sends complete refund data to backend API
5. POS app waits for manager to provide PIN from their mobile device

### Backend Side
1. Validates request data and authentication
2. Checks seat ownership
3. Appends refund record to seat's `refundRecords` array
4. Saves to database with `pending` status
5. Retrieves license owner's FCM tokens from `license.user.fcmTokens`
6. Sends push notification with refund details + PIN
7. Returns success response to POS client

### Admin Mobile App Side
1. Receives push notification with refund details
2. Reviews transaction details (receipt, amount, items, reason)
3. Makes decision to approve or reject
4. Provides 6-digit PIN to cashier if approved

### Completion (back to POS Client)
1. Cashier enters PIN provided by manager
2. POS validates PIN matches the one sent
3. POS completes refund transaction
4. Future enhancement: POS sends confirmation to backend to update status to `approved`
